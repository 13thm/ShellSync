

## 1. 项目概述
本项目旨在开发一套**电脑客户端 + 手机客户端双端同步的持久化终端任务管理系统**，核心目标是解决开发者本地运行 AI 命令行工具（Claude Code、Pi Agent 等）时，无法远程监控、无法随时干预、任务无管理、终端日志丢失、无法移动端随时操控的痛点。

系统通过电脑端独立后台守护进程托管系统终端会话，实现终端常驻、日志永久保存、任务不中断；手机端登录同账号实时同步电脑端所有终端、任务、待办数据，实现跨设备随时查看、操控、干预终端运行任务。

系统不以远程桌面投屏实现，**纯终端字符流同步**，轻量、高效、专注命令行任务管理。

## 2. 核心业务背景与用户痛点
用户日常大量使用 Claude Code、Pi Agent 等 AI 命令行编码工具，存在以下痛点：

+ 1. AI 终端任务运行时间极长（几十分钟～数小时），电脑不能随时盯屏
+ 2. 原生终端关闭窗口即终止任务，无法后台常驻
+ 3. 原生终端无日志永久保存，重启后无法回溯历史操作与 AI 思考过程
+ 4. 没有任务管理体系，多个 AI 终端任务混乱、无法归类、无法备注
+ 5. 没有待办体系，无法将终端任务与工作计划绑定
+ 6. 离开电脑无法查看、无法暂停、无法输入指令干预 AI 运行
+ 7. 市面所有终端工具（Termius、ttyd、Tmux）均无「任务+待办+双端同步」完整业务体系

## 3. 整体产品定位
一款**面向开发者的本地 AI 终端任务持久化、双端同步管控工具**。

定位区别于传统工具：

+ 不是 SSH 远程终端工具
+ 不是网页临时终端
+ 不是远程桌面投屏软件
+ 是**本地终端托管 + 任务管理 + 待办绑定 + 双端实时同步**的专属开发辅助系统

## 4. 功能需求总览（完整、无遗漏）
### 4.1 电脑端客户端核心功能（主服务端）
电脑端是整个系统的**数据源头、任务运行载体、终端托管核心**，包含完整管理体系。

#### 4.1.1 整体页面结构
电脑端 App 拥有完整客户端 UI，包含四大核心模块：

+ 任务管理
+ 终端管理
+ 待办任务管理
+ 个人中心与同步设置

#### 4.1.2 终端系统核心能力（最核心需求）
系统内置终端必须**完全等同于系统原生终端**，支持全部日常终端操作：

+ 支持 CMD / PowerShell / Bash / Zsh 完整切换
+ 支持运行 Node / Python / Go / 各类脚本
+ **完美支持 Claude Code、Pi Agent 等交互式 AI 命令行工具**
+ 支持 ANSI 颜色、进度条、交互式确认、动态输出
+ 多终端实例隔离，可同时开启多个独立终端任务

#### 4.1.3 终端持久化能力（核心刚需）
+ 关闭终端 UI 窗口，**后台任务继续运行不中断**
+ App 重启后可恢复所有终端历史记录与运行状态
+ **所有终端输入输出永久落盘保存**，可随时回溯完整操作过程、AI 思考日志
+ 每个终端拥有独立唯一 ID、名称、创建时间、归属任务

#### 4.1.4 任务管理模块
+ 支持创建、编辑、删除、命名业务任务
+ 一个任务可绑定一个或多个终端实例
+ 可标记任务状态：未开始、进行中、已暂停、已完成
+ 任务全程可追溯，关联对应终端完整日志

#### 4.1.5 待办任务模块
+ 支持创建开发待办事项
+ 待办可关联指定任务、指定终端
+ 支持待办状态流转、备注修改

#### 4.1.6 本地后台守护能力
+ 独立后台 Daemon 进程，不依赖 UI 界面
+ UI 程序退出不影响终端任务运行
+ 统一管理所有 PTY/ConPTY 终端会话
+ 统一管理本地数据库、日志存储、双端通信

### 4.2 手机端客户端核心功能（远程控制端）
手机端为同步与远程操作客户端，数据、列表、终端全部与电脑端实时同步，允许轻微延迟。

#### 4.2.1 账号体系
+ 电脑、手机登录同一账号实现数据同步

#### 4.2.2 数据同步能力
手机端实时同步电脑端所有数据：

+ 全部任务列表
+ 全部终端实例列表、运行状态
+ 全部待办任务列表

#### 4.2.3 手机终端操控能力（核心）
+ 手机可任意打开电脑端任意一个终端会话
+ 进入终端自动加载**全部历史日志**
+ 实时接收电脑终端最新输出
+ 手机可输入指令、回车执行、干预 AI 任务
+ 支持查看 Claude Code / Pi Agent 实时思考、代码修改、进度输出
+ 允许轻微网络延迟，不要求毫秒级实时

#### 4.2.4 移动端管理能力
+ 手机可查看任务详情、终端状态、待办进度
+ 支持基础状态更新（后续迭代可完善编辑能力）

## 5. 非功能需求（硬性约束）
### 5.1 稳定性需求
+ 终端后台可稳定运行数小时不卡死、不中断、不丢日志
+ 适配 Windows / macOS / Linux 全平台
+ 专门兼容 Windows ConPTY 机制

### 5.2 性能需求
+ 终端数据流轻量，只传输字符流，不传输画面
+ 双端同步延迟可接受 0～2 秒

### 5.3 兼容性需求
+ 完整支持 Claude Code、Pi Agent 所有交互式行为
+ 完整兼容 ANSI 终端颜色、光标、动态进度

### 5.4 数据持久化需求
+ 终端日志永久本地保存
+ 任务、终端、待办元数据永久保存
+ 重启软件不丢失、不重置

## 6. 明确的「非需求」（避免开发偏差）
为避免功能冗余、架构跑偏，明确本系统**不做**以下功能：

+ ❌ 不做远程桌面投屏、图形画面传输
+ ❌ 不接管电脑外部手动打开的 CMD/PowerShell 窗口（系统限制）
+ ❌ 不做手机本地终端，手机仅远程操控电脑终端
+ ❌ MVP 阶段不做多用户、权限分享、外网中继（后续迭代）

## 7. 技术方案需求（最终确定版）
经过多轮对比，本项目最终确定技术栈：

+ **后台守护进程 Daemon：GO**（稳定、独立进程、跨平台 PTY、长时间任务不崩）
+ **电脑客户端 UI：Electron + Vue3 + TypeScript + xterm.js**
+ **手机客户端：Flutter 跨端 App**
+ **通信协议：WebSocket 实时长连接**
+ **本地存储：SQLite**

## 8. 核心业务模型关系
**任务(Task) 1:N 终端(Terminal) 1:N 日志(Log)**

**任务(Task) 1:N 待办(Todo)**

一个业务任务可以绑定多个终端；一个终端归属唯一任务；所有终端操作全部留日志；任务可绑定多条待办记录。

## 9. 项目价值总结
本项目解决了 AI 编码时代开发者的刚需：**本地长时间 AI 终端任务无人值守、可远程监控、可随时干预、可全程回溯、可结构化管理**。

市面上无任何一款开源/商业软件完整具备本系统能力，项目具备极高的个人实用价值与开源项目创新性。
