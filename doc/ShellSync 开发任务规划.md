## M1. Daemon 基础（⬜ 未开始）

> 目标：跑起一个可被 Electron 拉起的独立 Go 进程，能持久化数据、托管一个真实终端。

| 编号 | 任务 | 状态 | 优先级 | 工时 | 依赖 | 验收标准 |
|---|---|---|---|---|---|---|
| M1-1 | 初始化 Go module + 目录骨架 | ⬜ | P0 | 0.5 | — | `daemon/` 下 internal 各包目录就位，`go build` 通过 |
| M1-2 | `config` 配置加载（数据目录、端口） | ⬜ | P0 | 0.5 | M1-1 | 读取 `~/.shellsync/config.json`，缺省值合理 |
| M1-3 | `lifecycle`：lock 文件 + 单实例 + 信号优雅退出 | ⬜ | P0 | 1 | M1-2 | 写 `daemon.lock`（pid/port/token），重复启动复用，SIGINT/SIGTERM 优雅关闭 |
| M1-4 | SQLite 初始化 + WAL + 自动迁移 | ⬜ | P0 | 1 | M1-1 | 启动即建 8 张表，WAL 模式开启 |
| M1-5 | `repository`：各实体 Repo（CRUD） | ⬜ | P0 | 2 | M1-4 | task/terminal/todo/log/devices/users/settings 全套 CRUD + 单测 |
| M1-6 | `pty` 跨平台抽象（Unix `creack/pty` + Windows ConPTY） | ⬜ | P0 | 2 | M1-1 | 能 spawn cmd/powershell/bash/zsh，读 stdout、写 stdin、resize、关闭 |
| M1-7 | `logstore`：chunk 聚合（16ms/16KB）+ seq 单调 + 落盘 | ⬜ | P0 | 1.5 | M1-5 | 持续输出按 chunk 入库，`(terminal_id,seq)` 唯一，冷归档文件追加 |

```
M0(文档) ──► M1(Daemon基础) ──► M2(Daemon接口) ──┬─► M3(Desktop) ──┐
                                                  │                  ├─► M5(联调发布)
```

- **关键路径**：M1 → M2 → M3（Desktop 是主验证端，建议先于 Mobile）。

## 建议执行顺序（Top-Down）

1. **先跑通单终端闭环**：M1-1 → M1-4 → M1-6 → M1-8（能 spawn 一个终端并看到输出）
2. **再补持久化**：M1-5 → M1-7（输出落库、可回放）
3. **打通接口**：M2-2 → M2-5（REST + WS）
4. **接上 Desktop**：M3-1 → M3-3 → M3-6（先有能用的终端 UI）
5. **补全 Desktop 业务**：M3-4 → M3-5 → M3-7 → M3-8
6. **再做 Mobile**：M4 全套
7. **压测发布**：M5

> 原则：**先纵向打通一条最窄可用链路（建终端→跑命令→看输出→落库），再横向铺开所有功能**，避免长时间没有可运行产物。

## 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Windows ConPTY 兼容性 | 终端在 Win 上异常 | M1-6 优先在 Windows 验证；预留 fallback 到 `winpty` |
| Claude Code/Pi Agent 交互式行为 | ANSI/光标渲染错乱 | M3-6 用真实 AI 工具做验收用例，原始字节透传不改写 |
| 日志高频写库性能 | 长时间运行卡顿 | M1-7 chunk 聚合 + WAL + 冷归档；M5-1 压测验证 |
| 局域网发现/防火墙 | 手机连不上 | M2-4 二维码直填 IP；文档说明放行端口 |
| Electron 拉起 daemon 跨平台差异 | 启动失败 | M3-1 三平台分别验证 detached 启动 |
