# R1-1 relay-server 骨架

**目标**:单二进制 HTTP 服务跑起来,带配置与可观测入口。**预估**:0.5d

**步骤**:
1. 📁 仓库根新建(与 daemon 平级,复用同栈技术):
   ```
   server/
   ├── cmd/relay-server/main.go        # 入口:装配 config→router→listen
   ├── internal/
   │   ├── config/config.go            # 读 config.toml(listen/tls/log)
   │   └── transport/http/router.go    # /health /metrics /ws(占位)
   ├── config.toml                     # dev 默认:127.0.0.1:8788
   └── README.md
   ```
2. 🔧 初始化模块:
   ```bash
   mkdir -p server && cd server
   go mod init github.com/shellsync/relay-server
   go get github.com/go-chi/chi/v5 github.com/go-chi/cors
   ```
   > 若希望与 daemon 同一个 go.work,根目录补 `go.work use ./daemon ./server`。
3. 📁 `config.go`:定义 `Config{Listen, TLS, LogLevel}`;`Load()` 读 `config.toml`
   (与 daemon 的 json 风格不同没关系,服务端独立);env 覆盖 `RELAY_LISTEN`。
4. 📁 `router.go`:`GET /health` 返回 `{status:"ok",ver}`;`GET /ws` 先返回 501 占位。
5. 🔧 本地起服务:
   ```bash
   go run ./cmd/relay-server
   curl http://127.0.0.1:8788/health   # {"status":"ok"}
   ```

✅ **完成标志**:服务可启动,/health 可访问,配置从 config.toml 读取。
🧪 单测:config 加载默认值/文件覆盖/env 覆盖三种。

# R1-2 帧协议 + /ws 端点

**目标**:定义 wire 协议并实现双角色 WebSocket 接入。**预估**:1d **依赖**:R1-1

**步骤**:
1. 📦 `go get github.com/coder/websocket`(与 daemon 同库)
2. 📁 `server/internal/relay/frame.go` —— 协议常量与编解码(对照《方案》§5.2):
   ```go
   // 控制帧(JSON 文本)
   //   hello {role:"daemon"|"client", ver:1}
   //   reg   {devId, sign}                 // sign = HMAC-SHA256(devSecret, devId+nonce+ts)
   //   code  {code, ttl}                   // daemon 注册配对码
   //   claim {code}                        // client 领取
   //   open  {streamId, devId}             // client→daemon 开流
   //   accept{streamId} / close{streamId, why}
   // 数据帧(二进制): [streamId:4B][len:4B][payload]
   func EncodeData(streamID uint32, p []byte) []byte
   func DecodeData(b []byte) (streamID uint32, p []byte, err error)
   ```
3. 📁 `server/internal/relay/session.go`:`Session` 封装一条 WSS 连接 ——
   并发安全的 `WriteControl()` / `WriteData()`,读循环分发到 handler 回调。
4. 📁 `router.go` 实现 `/ws`:首帧必须是 `hello`;按 `role` 分派到
   `DaemonHandler`/`ClientHandler`(R1-3 实现,R1-2 先校验 hello 并挂起连接)。
5. 🧪 `frame_test.go`:所有帧型 roundtrip;非法帧(超短/坏 JSON/未知 t)返回错误并断连。

✅ **完成标志**:两个 wscat/测试客户端能握手 hello,错误帧被拒。
🧪 用 `websocat ws://127.0.0.1:8788/ws` 手工发 `{"t":"hello","role":"client","ver":1}` 验证。

# R1-3 会话撮合、pipe 与限速

**目标**:云端核心逻辑 —— 内存表 + 流转发。**预估**:1d **依赖**:R1-2

**步骤**:
1. 📁 `server/internal/relay/hub.go` —— 全局状态(全部内存,无 DB):
   ```go
   type Hub struct {
     mu       sync.RWMutex
     daemons  map[string]*Session   // devId → daemon 连接
     codes    map[string]codeEntry  // code → {devId, expiresAt}  TTL 120s
     streams  map[uint32]*pipe      // streamId → {client, daemon}
     nextID   uint32
     claims   map[string]*limiter   // IP → 滑动窗口(5 次/min,超限拉黑 10min)
   }
   ```
2. 📁 处理链:
   - daemon `reg`:验 sign(见 R1-4 的密钥约定)→ `daemons[devId]=s`;
   - daemon `code`:`codes[code]={devId,now+120s}`;惰性清理过期;
   - client `claim`:查表 → 命中即删(一次性)→ 记下 client 会话待 `open`;
   - client `open{streamId?}`:服务端分配 streamId → 转发给目标 daemon;
   - daemon `accept`:建立 pipe;双方数据帧按 streamId 互转;
   - `close`/任一侧断连:清理 pipe 并通知对端。
3. 📁 限速:`golang.org/x/time/rate`,按 WSS 连接对端 IP;429 时回
   `{"t":"error","code":"rate_limited"}`。
4. 📁 优雅关停:SIGTERM → 关闭所有 pipe(向双方发 close)→ 退出。
5. 🧪 `hub_test.go`(集成测试,httptest+websocket dial):
   - [ ] reg+code+claim+open+accept 后,client 发的字节出现在 daemon 测试桩;
   - [ ] code 过期/重复 claim 被拒;限速触发 429;
   - [ ] 一侧断连,另一端收到 close。

✅ **完成标志**:`go test ./internal/relay/...` 全绿;单进程内完成全链路字节互通。

# R1-4 daemon 出站 relay 客户端

**目标**:daemon 作为云客户端:注册、心跳、重连、多路复用、流⟷本机端口。**预估**:1.5d **依赖**:R1-2

**步骤**:
1. 📁 `daemon/internal/transport/relay/client.go` 骨架:
   ```go
   type Client struct { url string; hcPort int; conn *websocket.Conn; ... }
   func Run(ctx context.Context, url string, hcPort int, id Identity) error
   // 生命周期:connect → hello(daemon) → reg → 循环{read, heartbeat 30s}
   ```
2. 📁 **Identity/devSecret**:
   - 首次启用云时生成 32B 随机 `devSecret`,存 `settings` 表(键 `relay.secret`),
     同时生成/复用 `devId`(daemon 装机 UUID,锁文件里已有就复用);
   - `sign = HMAC-SHA256(devSecret, devId+"|"+nonce+"|"+unix)`;云端只验签名形状
     (云端不存 secret,防冒充依赖 R1 的"注册即信任 + code 路由",R2 升级 PAKE)。
3. 📁 **流转发**:收到 `open/accept` 后 `net.Dial("tcp","127.0.0.1:hcPort")`,
   `io.Copy` 双向 ⟷ 数据帧;并发多流用 `map[uint32]*stream` + 互斥锁。
4. 📁 **重连**:指数退避(1s→2s→…→60s 封顶,jitter 20%);重连成功重发
   `hello/reg`(配对码需重新生成时由 service 层触发,见 R1-5)。
5. 📁 `daemon/internal/config/config.go` 扩展(默认 dev 地址,见《修改计划》§2.2):
   ```go
   type Cloud struct {
     Enabled bool   `json:"enabled"` // 默认 true
     URL     string `json:"url"`     // 默认 ws://127.0.0.1:8788/ws
   }
   ```
6. 📁 `cmd/shellsync-daemon/main.go`:HTTP 服务起来后 `go relay.Run(ctx, ...)`;
   优雅退出时关闭云端连接。
7. 🧪 `client_test.go`:本地起 hub(R1-3)→ daemon client 连上 → 测试桩 client
   open 一条流 → 发 HTTP `GET /health` 原始字节 → 收到 daemon 的 HTTP 响应。
   (这条测试就是"隧道打通"的最小闭环。)

✅ **完成标志**:daemon 连上本机 relay,外部测试桩能经隧道访问 daemon 的 /health。

# R1-7 mobile 隧道传输层

**目标**:Flutter 侧把隧道流伪装成 socket,上层 RestClient/WsClient 零改动。**预估**:1.5d **依赖**:R1-3

**步骤**:
1. 📦 依赖:`web_socket_channel`(项目已有 WS 依赖则复用)。
2. 📁 `mobile/lib/api/relay_transport.dart`:
   ```dart
   class RelayTransport {
     // 1) WSS 连 cloud;hello(client)
     // 2) pairCode 流程:claim{code} → open{devId} → accept → 流就绪
     // 3) 日常流程:直接 open{devId}(token 在流内 HTTP 头里带,daemon 原有鉴权)
     // 4) 提供:
     //    Stream<Uint8List> get stream;   // 收
     //    void send(Uint8List bytes);     // 发(带 streamId 分帧)
     //    Future<void> close();
     //    断线重连(指数退避)+ 状态流:connecting|online|offline
   }
   ```
3. 📁 **HTTP over 隧道**:`lib/api/relay_http_client.dart` —— 实现极简 HTTP/1.1
   编解码(把 `rest_client.dart` 的请求行/头/体写成字节发出去、按 Content-Length/
   chunked 读回)。`RestClient` 增加可选 `transport` 参数,有则走隧道,无则原样 dio。
   > 只需覆盖项目实际用到的子集:JSON GET/POST/PATCH/DELETE、无文件上传。
4. 📁 **WS over 隧道**:`WsClient` 改造为可注入 `StreamChannel`,`relay_transport`
   提供 channel(首帧带 token 与 `Connection: Upgrade` 语义由 daemon 本机 WS 处理,
   隧道只透传字节,升级天然成立)。
5. 🧪 单元:本地起 Go relay+daemon(测试脚本),Flutter widget test 里发
   `GET /health` 经隧道拿 200;WS echo 一帧。

✅ **完成标志**:不碰 stores/views 的前提下,`RestClient`/`WsClient` 能跑在隧道上。
