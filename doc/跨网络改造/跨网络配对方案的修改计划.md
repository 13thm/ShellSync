# 跨网络配对方案的修改计划

> 版本:v1.0 ｜ 配套《跨网络配对方案.md》(总设计)与《开发步骤程序.md》(逐任务步骤)
>
> **核心原则:一套代码跑所有环境。本地测试与生产上线之间只差配置文件,
> 不改一行代码、不重新编译。**

## 2. 配置驱动设计(本计划的关键)

### 2.1 环境矩阵

| 环境 | relay 地址 | TLS | 用途 | 怎么切 |
|------|-----------|-----|------|--------|
| **dev** | `ws://127.0.0.1:8788/ws` | 无 | 本机三件套自测(daemon+relay+模拟客户端) | 默认值即 dev |
| **staging** | `ws://<测试机局域网IP>:8788/ws` | 无 | 手机真机连测试 relay(免证书,快速验证) | 手机端 debug 覆盖 |
| **prod** | `wss://relay.shellsync.example.com/ws` | Caddy+Let's Encrypt | 正式上线 | 改 3 处配置文件(见 §2.3) |

### 2.2 配置文件清单

**① relay-server:`server/config.toml`**

```toml
# dev(本地测试)
listen = "127.0.0.1:8788"     # 只听本机
tls = false                    # dev 不需要

# prod(VPS 上另一份)
# listen = ":8788"            # Caddy 反代 443→8788,见 deploy/relay/
# tls = false                 # TLS 由 Caddy 终结,进程内仍关
```

**② daemon:`~/.shellsync/config.json`**

```jsonc
{
  "httpPort": 8787,
  "cloud": {
    "enabled": true,
    "url": "ws://127.0.0.1:8788/ws"      // dev;上线改成 wss://relay.shellsync.example.com/ws
  }
}
```

> `devSecret`(daemon 云端身份密钥)不入配置文件:首次启用云连接时自动生成,
> 存 SQLite `settings` 表 —— 避免用户手抄,也避免提交进 git。

**③ mobile:构建期默认值 + 运行期覆盖**

```bash
# dev/staging:不传则用代码里的 dev 默认(127.0.0.1:8788);
# 真机连局域网测试机时,在 App「设置 → 开发者」里临时覆盖 relay 地址(debug 构建才有此入口)

# prod 打包:
flutter build apk --dart-define=RELAY_URL=wss://relay.shellsync.example.com/ws
```

配对成功后手机实际使用的是**二维码里带的 `cloud` 字段**,构建期默认值只影响
"扫码前".所以生产部署时**真正要改的只有 daemon 的 cloud.url** —— 手机端跟随二维码走,
无需发版。

**④ desktop:零配置**。它读 daemon 的 settings API 显示云状态,永远连 127.0.0.1。

### 2.3 上线切换动作(总共 3 步)

```
1. VPS 部署 relay-server(docker compose + Caddy,见《开发步骤程序.md》R1-10)
2. 改 ~/.shellsync/config.json 的 cloud.url → wss://relay.shellsync.example.com/ws
3. 重启 daemon(重开 ShellSync 即可;或托盘菜单「重连云端」)
```

旧二维码/旧 App 不受影响(v2 兼容 v1,降级为局域网模式)。

## 3. 阶段计划

### P0 本地自测(不改任何配置,纯本机)

```
范围:relay-server + daemon relay 模块 + Go 单测/集成测试
验收:go test 覆盖 帧协议/重连/限速/流转发;本机起三件套,
     用 curl 经隧道打通 daemon 的 /health
```

| 事项 | 说明 |
|------|------|
| relay-server 起在 127.0.0.1:8788 | `go run ./cmd/relay-server` |
| daemon cloud.url 指本机 | 默认值就是,无需改 |
| 隧道连通性 | 用 Go 测试客户端(不需要手机)模拟 open 流 → 打 daemon /health |

### P1 真机联调(局域网 staging)

```
范围:手机 App 接入(扫码跨网模拟)
验收:手机连蜂窝网络(关 WiFi)扫码配对成功,终端可输入输出,断网重连恢复
```

| 事项 | 说明 |
|------|------|
| relay-server 跑在开发机局域网 IP | 手机和电脑**不在同一网段**时用手机流量连公网不可行,改为:手机连 A 网络、电脑热点 B?→ 更简单的做法:手机开流量,连 frp/staging 公网;或先验证「手机连 relay、relay 与 daemon 同机」的链路 |
| 手机 debug 构建覆盖 relay 地址 | 设置 → 开发者 → relay 地址 |
| 重点回归 | 同网直连仍走局域网(不能因为加了云把快路径弄坏) |

> P1 的意义:在花 VPS 钱之前,用真机把手机端代码全部验证完。

### P2 部署生产 relay(一次性)

```
范围:买 VPS、域名、Caddy TLS
验收:外网 curl https://relay.../health 返回 200;证书有效
```

| 事项 | 说明 |
|------|------|
| VPS | 2C4G 起,国内(需备案)或香港(免备案、延迟+30ms) |
| 域名 | `relay.shellsync.example.com` A 记录 → VPS |
| 部署 | `deploy/relay/docker-compose.yml`(relay + Caddy),`docker compose up -d` |
| 防火墙 | 只开 443;8788 仅监听 127.0.0.1(Caddy 内部转发) |

### P3 切换上线(改配置,见 §2.3)

```
范围:自己先用 → 灰度发给少量用户 → 全量
验收:新用户扫码即跨网可用;老版本一切照旧
```

### P4 运行期开关与回滚

| 操作 | 做法 | 效果 |
|------|------|------|
| 单台电脑退出云 | daemon config `cloud.enabled=false` → 重启 | 该机回纯局域网,手机连它的云路径失效,局域网照常 |
| 全体回滚 | 关掉 VPS 上 relay 容器 | 所有手机云路径断,自动回落局域网;**不需要发版** |
| 封禁滥用 | relay 黑名单配置/防火墙 | 按 IP/devId 拉黑 |

**回滚零风险的原因**:云是纯增量路径,局域网主路径从未改动;
任何云侧故障的最坏结果 = 退回现状(与今天未上线云时完全一致)。

## 4. 测试检查清单(上线前必须全绿)

### 4.1 P0 单元/集成(daemon + relay)

- [x] 帧协议编解码 roundtrip(控制帧 + 二进制数据帧)— `server/relay/frame_test.go`、`mobile/test/relay_protocol_test.dart`
- [x] daemon 断线重连:杀掉 relay → 重启,daemon 自动恢复注册 — `TestClientReconnects` + dev 联调实测
- [x] code TTL 过期后 claim 被拒;code 一次性(二次 claim 拒绝)— `TestCodeExpiry`/`TestCodeOneShot`
- [x] claim 限速:同 IP 6 次/分钟 → 第 6 次起 429 — `TestClaimRateLimit`(错误帧 rate_limited)
- [x] 隧道大流量:10MB 连续输出不卡死(背压/分帧正确)— `TestTunnelBulkAndConcurrency`(10MB 单流 + 3 并发流)
- [x] 多并发流:同时 3 条流互不串台(streamId 隔离)— 同上
- [x] 补充:daemon verify 失败锁定(3 错锁 5min)— `daemon/internal/service/pair_test.go`
- [x] 补充:隧道内 Authorization 头/token 鉴权原样穿透(relay 不解析业务)— dev 联调实测(无 token 401)

### 4.2 P1 真机

- [ ] 手机流量 + 电脑在家:扫码 → 配对成功 → 终端交互正常
- [ ] 手机 WiFi 与电脑同网:走局域网直连(状态栏显示"局域网")
- [ ] 同网时拔掉路由器外网线:App 自动切云(或断线提示→重连成功)
- [ ] 杀 App 重开:自动用已存凭证连上,无需重新扫码
- [ ] Desktop 设备管理删除手机:该手机云路径立即失效

### 4.3 P2/P3 生产

- [ ] `curl https://relay.../health` 200,证书链完整
- [ ] daemon(config 指生产)注册成功,Desktop 显示"云端已连接"
- [ ] 手机流量扫码全流程
- [ ] 旧版 App(v1 二维码解析)扫新码:退化为局域网,不崩溃
- [ ] 回滚演练:停 relay 容器 → 手机回落局域网路径正常

## 5. 风险与对策

| 风险 | 影响 | 对策 | 阶段 |
|------|------|------|------|
| 配对码公网枚举 | 陌生人在 2min TTL 内猜中 6 位码 | 云端限速+code 一次性;R1 即上线 | P2 前必须 |
| 云端单点故障 | 全体用户跨网不可用 | 自动回落局域网;VPS 重启秒级恢复(compose) | 设计内 |
| 明文经云 | 终端内容可见于云 | R2 上 SPAKE2 + E2E 加密;在此之前 README 明示 | R2 |
| devSecret 泄露 | 他人冒充该 daemon | secret 存本地 DB 不出网(只以 HMAC 形式出现);可吊销重生成 | P0 |
| 手机端构建默认值写死公网 | 测试环境连生产 | dev 默认走 127.0.0.1;生产值仅 `--dart-define` 注入 | 全程 |

## 6. 工作量与排期估算(单人,1 人天=6h)

| 阶段 | 内容 | 工时 |
|------|------|------|
| P0 | relay-server + daemon relay + 测试 | 4~5d |
| P1 | 手机端隧道与连接策略 + 真机联调 | 3~4d |
| P2 | VPS/Caddy/域名/部署脚本 | 0.5d |
| P3 | 切换、灰度、文档 | 0.5d |
| **R1 合计** | | **8~10d** |
| R2 | SPAKE2 + E2E 加密 | 3~4d(另行细排) |

> R1 完成即达成"装软件→扫码→任意网络可用"的最小闭环;R2 是安全补强,不影响功能面。
